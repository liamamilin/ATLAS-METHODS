# 本机 Skill 资料库

按领域、专题和仓库查看已经转换的 Skill。搜索覆盖标题、任务目标、摘要和来源。详情展示适用条件、步骤、产出与限制，可以复制做法，或打开固定版本的 GitHub 来源和本机原文。

在本机搜索框可输入任务描述，例如「给 React 列表进入详情时加一个过渡动画」。目录用保存的任务目标、适用条件、产出和常用别名检索，每张结果卡显示同一条 Skill 中命中的一个任务。点击卡片会展开该任务。选择二级分类后，「做什么」和「适用工具」显示该分类可用的标签。选择标签后，目录显示与当前标签、关键词和来源匹配的条数。标签从已有任务内容生成，重建本机目录时一并生成任务索引。

选择一个领域会展开带条数的二级分类，分类可与关键词和来源筛选一起使用。规则根据标题、任务目标、入口目录名和摘要初分。信号冲突或用途不明确的记录归入该领域的「待细分」。法律来源已有明确专题的条目沿用专题。

「待归类」按标题、入口目录名和任务目标里的方向线索分组，便于逐批复核。「跨领域线索」表示出现不同领域组的线索，「线索不足」表示这几项里没有明确方向。

在仓库根目录使用现有标准化 Python 环境运行：

```bash
python3 library/build.py
python3 library/serve.py --port 8765
```

打开 [本机资料库](http://127.0.0.1:8765)。服务只监听本机地址。完整资料库和原文由本机提供，生成的 SQLite 索引保存在 `data/library/catalog.sqlite3`。

目录重建会替换这份 SQLite。人工目录归类写在 `data/library/classification-overrides.json`，由重建读回，不直接改数据库，也不运行公开导出。预览、写入、核对和回滚命令见 [分类覆盖层操作说明](../docs/classification-overrides.md)。

服务已在本机 8765 端口运行时，下面的请求只读现有目录，不重建、不导入、不改端口：

```bash
curl -fsS 'http://127.0.0.1:8765/api/meta'
curl -fsS 'http://127.0.0.1:8765/api/skills?q=视图过渡&category=code'
curl -fsS 'http://127.0.0.1:8765/api/skills?category=unfiled&topic=专业方向线索'
curl -fsS 'http://127.0.0.1:8765/api/skill/代表身份'
```

`/api/meta` 给出目录时间、代表数、领域和专题。`/api/skills` 接受 `q`、`category`、`topic`、`action`、`tool`、`repo`。`/api/skill/代表身份` 给出分类、`label_from`、任务步骤和固定版本来源。页面上的审阅状态来自转换记录，目录归类显示为「目录归类，未审源文」。

合成目录的页面冒烟不读取本机 `catalog.sqlite3`。机器上有 Chrome 时会打开真实页面：

```bash
python3 -m unittest discover -s library -p 'test_frontend_smoke.py'
```

验收清单见 [本机资料库验收清单](../docs/local-acceptance.md)。本机目录已经生成、服务已在 8765 端口运行时，用下面的命令做只读验收。它不重建、不导入、不另开端口：

```bash
python3 library/accept_local.py --require-server --page
```

没有 Chrome 时去掉 `--page`，只核对目录文件和接口是否同一份数据。`--shots /临时目录` 可留下页面截图。8765 已有服务时不要再次执行 `library/serve.py`。

## GitHub Pages 公开目录

[公开目录](https://liamamilin.github.io/ATLAS-METHODS/) 可以搜索 Skill 名称、分类和仓库，详情列出 GitHub 固定版本来源。部署源为 `gh-pages` 分支根目录。

在仓库根目录构建最新快照，然后导出到一个空目录：

```bash
python3 library/build.py
python3 library/export_pages.py /tmp/atlas-pages-release
```

公开目录包含条目标题、目录标签、来源元数据，以及 `public-overviews.json` 逐条选出的公开整理摘要。每条摘要核对本机记录的来源路径和固定提交，并保留上游作者与许可。公开搜索可查标题、已公开摘要和来源路径，长横线、连字符和空格可互换。公开详情提供「在本机查看完整整理」入口。

更新公开站点时，把生成的 `index.html`、`app.js`、`pages_catalog.js`、`style.css`、`catalog.json` 和 `.nojekyll` 提交到 `gh-pages`。完整转换内容和原文仍用本机资料库访问。

后续转换落盘后再运行一次 `python3 library/build.py`，然后刷新页面。生成器读取启动时的已保存结果，原子替换目录。已打开页面的来源链接使用固定来源身份，代表记录变动时，旧链接仍可解析到当前代表。

目录从实际存在并与采集索引匹配的 SkillRecord 生成，复用首批 40 条和 `full-001` 正式结果。材料包合并比较固定版本的入口、关联文件 Git blob 和供给范围，额外识别能核对的 Markdown 格式变化。原转换与来源均保留，已核验的历史去重关联在代表条目的来源页可回查。存在重要内容差异或证据不足的记录各自保留。

分类沿用[既有内容分布抽样](../docs/content-distribution-20261118.md)中的类别。已有样本标签优先，其余按标题、任务目标和摘要初分，部分来源有可识别的专题。归属不明的条目保留在「待归类」。详情标出分类依据和记录审阅状态。

对于原先待归类的条目，明确的标题用语可补充分组，例如 Git 分支管理、Skill 制作、产品定价和演示文稿制作。标题明确描述应用连接与自动化的 Rube MCP 条目纳入「工具集成与自动化」。两类以上线索冲突时仍保留待归类。
